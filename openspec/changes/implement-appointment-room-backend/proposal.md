## Why

即时语音房、房主管理与基础举报的本地后端已交付，下一步需要让用户提前安排交流时间并获得确定的预约名额。预约仍未进入 current specs，本 change 将经用户确认的预约基础独立提出，不照搬历史 PRD 中的提醒、爽约处罚或时间限制。

## What Changes

- 新增预约房间的创建、发现和详情，包含明确的开始/结束时间；到点自动开放、到期复用既有结束流程。
- 提供预约及取消预约，预约占位，实际入房不能抢占其他人的有效预约席位；预约不是 membership，也不授予实时凭证或举报资格。
- 用户明确选择：到开始时间后成员无需等房主即可进入；开始后 5 分钟房主仍未上线，由当前在线成员中加入最早者（第二麦）接任，原房主迟到不自动恢复权限；满 5 分钟时无人在线则直接结束；此后只要最后一人退出、房间变为空房，立即结束，不再等待。
- 复用已有实际 join、身份历史、房主管理、LiveKit outbox 与到期清理，补齐预约与加入之间的事务容量边界。
- 提供持久、可恢复的时间调度和唯一 OpenAPI contract，验证时间边界、席位竞争、取消/加入竞态及旧接口兼容。

### Confirmed Scope

- 用户确认先做预约基础：创建、预约/取消预约、定时开放和结束；提醒与爽约限制独立后续推进。
- 用户确认预约占用实际名额、人数不得超过容量，并优先保障预约成员；房主缺席不阻止成员按时进入。随后补充：满 5 分钟仍未到场，由第二麦自动接任；满 5 分钟无人在线直接结束；超过 5 分钟，只要房间无人（最后一人退出），立即结束，无论此前是否有人上线。计划结束更早时优先结束。
- 本次生成规划文件，实施需在审阅后另行 apply。现有 LiveKit/房主管理 Cloud smoke 仍未执行，不随预约规划变为 PASS。

### Proposed Details for Review

- 容量包含房主，创建时为房主保留一个预约席位；其他用户最多预约剩余容量。房主可在未开始前取消整个预约房间，不能单独释放自己的保留席位后仍承诺房主资格。
- 未使用的预约席位保持到主动取消、房间取消或结束，不设置未确认的迟到释放期限。成功实际加入时原子消耗预约；之后离开/移除按既有规则释放实际名额，重进不自动恢复预约优先权。
- 新预约仅在开始前接受；未使用预约在开放后仍可取消。预约不是自动入房，实际加入仍重新验证账号、规则、密码和房间状态。
- 本次不提供改期；需要调整时先取消未开始房间再新建。开始/结束时间使用带时区的时间戳，要求开始晚于创建时服务器时间、结束晚于开始；不擅自引入提前天数、时长或跨房间重叠限制。

### Non-goals

- 不做提醒渠道、推送/邮件、倒计时广播、爽约计次/处罚、预约创建禁用、候补或预约席位迟到自动释放。5 分钟首次到场超时接任与满 5 分钟后的空房立即结束属于本次基础房间管理，不计爽约或处罚。
- 不做改期、延长时间、每人房间数量/跨房间冲突限制、房间历史界面、好友、前端/Figma 或生产部署。
- 不重复创建 LiveKit adapter、媒体 room、房主管理服务、举报资格表或第二套 API contract。

### Future Roadmap

- 预约提醒与爽约规则分别提出 change；历史 U-021 提醒渠道仍待决，历史 U-029 占位关系按本次明确选择进入提案。
- 前端按确认的 Figma 接入预约状态、本人预约和实际加入流程，再补设备与产品验收。

### Unresolved Decisions

- 占位、成员先入房、5 分钟接任，以及满 5 分钟后当前无人在线即结束均已确认，无阻塞规划的问题。上列 Proposed Details 随提案一起审阅，不能当作已实施事实。

## Capabilities

### New Capabilities

- `appointment-rooms`: 预约房间时间状态、占位预约、取消、实际入房优先保障、房主首次缺席与恢复调度的后端行为。

### Modified Capabilities

无。即时房间的已批准需求保持不变；预约作为新能力复用已批准的会话、实际 membership、房主管理与举报规则，不重写其他 active change 的 delta。

## Impact

- Impacted delivery stages: Architecture、Backend / API、Test / Acceptance。
- 主要影响 rooms 的 schema、事务容量、join/详情/列表边界与预约入口，及既有 voice/queue runner 的调度接入。
- Room 新增 kind 与 SCHEDULED/CANCELLED 状态，独立 reservation model；历史 Room backfill INSTANT，不能将预约记录伪装成已加入 membership。
- 新预约 API 与现有即时 API 保持边界；现有即时创建和默认列表不混入未开放预约。NestJS code-first 生成 `openapi/openapi.yaml`。
