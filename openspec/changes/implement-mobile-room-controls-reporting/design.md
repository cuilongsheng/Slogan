## Context

Figma 114:2510 是成员管理页；111:882、111:906、111:872、111:842 分别为邀请、房主退出接任、移除确认和举报覆盖层。语音页卸载会断开 LiveKit，因此操作界面必须保留当前语音会话。

## Decisions

1. 成员列表按服务端 position 排序；房主可移除其他 ACTIVE 成员，普通成员可举报其他人。房主也可举报。
2. 离房接任使用现有 `/leave` 的 `successorMembershipId`；仅列出当前 CONNECTED 的非房主 ACTIVE 成员，未指定仍可使用服务端默认第二麦。
3. 成员移除/重新邀请携带当前 `credentialVersion`，成功后刷新；冲突提示重新取成员状态。服务端 `/members` 只返回 ACTIVE，因此新增仅当前房主可读的 `/rooms/{roomId}/removed-members`，返回最小的已移除成员身份与版本，用于重邀。
4. 普通邀请候选由 `/v1/people/available` 和好友 API 提供，发送时仍由服务端复核。邀请不预留名额。
5. 举报使用一次性 UUID 作为 clientRequestId，同一提交在网络失败后重试保持 UUID 和内容；改变目标、类别或说明时换 UUID。成功只显示受理编号，不在房间广播。
6. 现有成员响应没有举报所需的 targetUserId。只向已通过同房间成员资格校验的调用者在 ACTIVE 成员列表中补充 `userId`，继续由举报端点独立验证历史成员关系；不向公开分享码响应暴露成员 ID。
7. 已移除成员读接口在数据库锁内校验当前房主和有效房主成员身份，仅返回该房间已移除成员；新房主在移交后可管理，旧房主立即失权。

## Risks and rollback

- 成员列表/角色可能在操作时变化：服务端校验是最终权限边界，409 时刷新并提示。
- 举报正文敏感：仅提交到现有举报端点，不记入日志或客户端持久存储。
- 成员用户 ID 可见范围扩大：保留现有 `members` 权限检查，新增字段只出现在认证且仍为同房成员的响应；回滚移除该字段和前端举报目标入口。
- Web 操作与布局可验证；双设备 LiveKit 断线和移除后的旧凭证拒绝仍需真实设备及 Cloud 验收。
