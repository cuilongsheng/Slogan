## Context

Currently `apps/mobile` uses Expo Router, but only the project startup page; `packages/api-client` has no generated results or consumers. `openapi/openapi.yaml` is generated by the NestJS code-first process, is the only release contract, and the current workspace has an independent backend that has not committed changes. This change does not change the API policy or the contract itself.

## Goals / Non-Goals

**Goals:**

- Deterministically generate TypeScript paths, parameters, and response types from the same OpenAPI input, and provide drift checking.
- Provides `openapi-fetch` typed client factory in the package public entrance; the mobile terminal only accesses this public entrance through `src/api`.
- Allow the next batch of business features to inject the base URL, `fetch` and subsequent authorization processing without spelling out the URL or copying the DTO on the page.

**Non-Goals:**

- Does not implement refresh, persistent session or query cache when there is no real logged-in consumer; does not call business API or render unfinished product page.
- Does not automatically generate components from Figma, does not change the confirmed visual draft, and does not claim that this change has completed visual acceptance.

## Decisions

1. Use `openapi-typescript` 7.x to generate `packages/api-client/src/generated/schema.d.ts` from repository unique YAML, verify drift using CLI's `--check`. The current generator peer only accepts TypeScript 5, so TypeScript 5.9 is fixed in the generated package isolation; the mobile terminal continues to use the repository's TypeScript 6 to check the generated type. Its static output is submitted with the code; subsequent API contract changes must be regenerated. This preserves contract origin and reduces maintenance compared to handwritten types and home-made parsers.
2. Use `openapi-fetch` as a lightweight typed runtime. Package export `createSloganApiClient({ baseUrl, fetch? })`; does not read the Expo environment, store tokens or determine business error copy in the package. Reuse selected fetch boundaries compared to Axios or custom request layers.
3. `apps/mobile/src/api` is only responsible for mobile terminal operation configuration and future authentication injection; the first batch does not create consumerless global status or feature request combinations. The development configuration must explicitly give the accessible API base URL, and cannot silently use the local `localhost` as the physical device address.
4. Keep the existing bootstrap route first, so that the verification of this change focuses on generating contracts and Expo import; the first product route is implemented in the certification/material change with the exact Figma frame.

## Risks / Trade-offs

- [Contract changes with current uncommitted backend changes] → Generation and checking always use the current `openapi/openapi.yaml` of the workspace as input; the file is not modified, and the workspace status on which the generation is based is stated in the acceptance.
- [Add diff for large build files] → Disable manual editing, only allow fixed build commands; CI/local `--check` found drift.
- [The generator has not declared support for TypeScript 6 yet] → Limit TypeScript 5.9 to the development dependency of the generated package. Real consumers use TypeScript 6 to pass typecheck; the isolated version will be removed when the generator supports 6 in the future.
- [The emulator and physical device API addresses are different] → The factory requires the caller to explicitly configure it, and provide corresponding configuration and runtime evidence for the device environment when the next batch of connections is made.
- [Currently only project page] → Only infrastructure verification is reported, and login or room functions are not written as implemented.

## Migration Plan

Incrementally install dependencies, generate files, and add public entries without migrating persistent data or changing existing routes. Remove the new generation/runtime code and mobile entry of this package when rolling back, and restore the package list and lockfile; the backend and API contracts are not affected.
