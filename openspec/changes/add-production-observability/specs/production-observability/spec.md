## Purpose

为 Slogan 的客户端、服务端和异步运行入口提供可定位版本与代码位置的最小故障观测，并通过独立外部探测发现应用或调度停止。观测必须遵循现有隐私、审计和业务边界，以真实运行与通知送达证据建立故障发现闭环。

## ADDED Requirements

### Requirement: 采样性能追踪与语音技术质量聚合

用户批准的第二阶段 SHALL 只在 Error Monitoring + Tracing 范围内增加可配置的客户端 HTTP、语音连接/重连和有界本地连接质量 span。采样默认 0.1，支持 0；不得新增 Logs、Profiling、Application Metrics、音频/身份/私人内容或全量成功率宣称。跨端关联 SHALL 仅向指定 API origin 的 /v1 路径传播经过白名单处理的技术 trace header，span 名称来自 OpenAPI 模板。

#### Scenario: 客户端 API 请求关联

- **WHEN** 已启用采样的客户端向配置 API 发起受支持请求
- **THEN** 使用固定 schemaPath、HTTP 方法/状态与有限耗时进行观测，向其他 origin/路径及重定向目标不传播关联数据，原请求和认证结果不变

#### Scenario: 语音正常恢复与质量变化

- **WHEN** 连接或重连成功、失败，或本地连接质量等级发生变化
- **THEN** 在采样与数量上限内保留技术阶段结果和耗时；主动退出/移除/正常结束不产生错误，且不记录成员或房间身份

### Requirement: 启用的运行入口提供可关联的故障事件

系统 MUST 在已启用监控的 Admin、Mobile Web、Mobile 原生、API、队列消费者和实际运行的独立 worker 中记录非预期程序异常与系统失败，包括被应用错误边界捕获的失败。每个事件 MUST 包含可信的环境、服务、平台、发布版本和构建标识，以及允许的稳定错误类别；HTTP 事件 MUST 在存在合法请求标识时提供与服务端日志一致的技术关联。预期业务拒绝 MUST 不作为程序异常告警，转换成稳定服务错误的依赖故障 MUST 不因已捕获而消失。

#### Scenario: 全局过滤器捕获依赖故障

- **WHEN** 已启用监控的 API 将依赖不可用转换为稳定服务错误
- **THEN** 系统产生一个归一化故障事件，可按环境、版本、服务及合法请求标识定位，不回传内部详情给客户端

#### Scenario: 预期业务拒绝

- **WHEN** 请求因密码错误、房间已满、无权限或已知状态冲突被拒绝
- **THEN** 系统保留既有业务响应，不发送程序异常告警，不影响真正系统失败的记录

#### Scenario: 重试中的同一失败

- **WHEN** 同一操作在 transport、应用边界或队列重试路径重复观察到失败
- **THEN** 系统按稳定类别聚合并限制重复通知，同时保留必要发生计数和最终失败状态，不把每次重试变成独立告警

### Requirement: 故障定位对应实际发布产物

系统 MUST 使受支持发布包的非受保护内容故障定位到对应版本的源码文件、函数及行号。移动端原生崩溃 MUST 使用匹配的原生构建符号；不同平台、构建与更新 MUST 不错误共用定位产物。定位产物和上传凭证 MUST 只通过受控构建路径传输，不作为公开静态资源或客户端运行凭证发布。

#### Scenario: 压缩 Web 发布包发生异常

- **WHEN** 实际发布的 Admin 或 Mobile Web 构建触发允许定位的异常
- **THEN** 观测平台显示对应源码位置与发布版本，公开站点不能下载该构建的 source maps

#### Scenario: 原生发布包发生崩溃

- **WHEN** 受支持的原生 release 构建发生可采集的原生崩溃
- **THEN** 观测平台能够使用匹配构建的符号定位，不将模拟器、开发环境或其他构建的定位结果作为该发布包证据

### Requirement: 所有观测通道遵守内容最小化

系统 MUST 在向第三方传输或在本地缓存观测信息之前移除非白名单字段。观测不得包含原始音频、转写、房间消息、笔记、举报正文、提示词、生成内容、原始请求/响应、SQL 及其参数、账号联系方式、身份或认证凭据、连接串、分享码或可还原私人内容；不得通过 URL、异常消息、嵌套 cause、breadcrumbs、附件、设备缓存或原生通道绕过。后台鉴权、校验、审计及持久化失败 MUST 只发送固定事件名、合法技术关联和稳定结果码，不发送 stack 或受保护上下文。首期 MUST 禁用会话回放、局部变量及任意内容附件，外部留存与访问 MUST 符合目标环境明确批准的数据政策。

#### Scenario: provider 错误夹带敏感内容

- **WHEN** 错误对象、cause、URL 或 breadcrumb 含 token、SQL、转写或 provider 原始响应
- **THEN** 捕获到的出站观测与本地观测缓存仅包含白名单技术字段，敏感值不能被恢复

#### Scenario: 后台审计失败被观测

- **WHEN** 后台审计或其他受保护后台路径发生异常
- **THEN** 观测只包含固定事件名、合法技术标识和稳定结果码，不包含 stack、操作正文或审计资料

#### Scenario: 原生崩溃后启动补报

- **WHEN** 原生应用重启并补发上次崩溃记录
- **THEN** 补报和此前本地缓存均遵循相同内容白名单，不依赖仅在 JS 发事件时运行的清理逻辑

### Requirement: 观测故障不改变业务和恢复语义

系统 MUST 将错误上报、告警与心跳网络操作同业务提交、真人语音和任务结果隔离。监控服务超时、拒绝或额度耗尽 MUST 不撤销已提交结果、不阻止进房/离房和音频、不吞掉应重试的队列错误，也不得将成功任务变成重试。发送与退出前排空 MUST 有限时和资源上限，监控投递不得进入无限重试或递归告警。

#### Scenario: 离房成功但监控超时

- **WHEN** 离房事务已提交且错误平台或心跳服务不可用
- **THEN** 既有离房结果和客户端断开语义不变，监控操作在限时后结束

#### Scenario: 消费者业务失败

- **WHEN** 队列消费者执行业务失败并尝试上报
- **THEN** 无论上报成功与否，原任务继续遵循既有失败重试语义，重复投递仍由既有业务幂等处理

### Requirement: 外部探测发现服务不可用和调度停止

系统 MUST 提供独立于业务鉴权的最小存活及就绪状态，存活表示进程可服务，就绪表示必要核心依赖可服务；不可就绪 MUST 返回非成功状态。探针 MUST 不返回依赖地址、凭据、用户/房间信息或受保护后台健康明细。外部监控 MUST 能在应用或监控调度进程完全停止时按已配置检查周期和宽限窗口通知指定接收人。调度心跳 MUST 仅在对应有意义的检查或恢复扫描完成后发送，不以函数启动或接收到消息代替完成。

#### Scenario: 核心持久层不可用

- **WHEN** API 进程仍能响应但核心持久层不可用
- **THEN** 存活探针与就绪探针表达不同结果，就绪返回非成功状态，响应不含内部诊断资料

#### Scenario: 无用户请求时扫描链停止

- **WHEN** 所有用户请求停止且关键恢复扫描或监控扫描不再完成
- **THEN** 外部心跳监控在配置窗口到期后通知指定接收人，不依赖新的用户请求或失效进程主动报错

### Requirement: 最小监控调度与治理清理独立

系统 MUST 在目标运行环境中执行独立的只读依赖/持久命令超期探测和告警投递，不依赖 HTTP 函数存活期间的定时器。重复、并发或重启后的扫描 MUST 不重复制造当前故障或丢失达到阈值的事实；恢复后 MUST 保留可识别的恢复状态。启用此监控 MUST 不启用数据保留删除、修改治理政策或开放原有受保护写操作。故障通知 MUST 复用已有持久告警重试能力，后台角色与审计边界保持原要求。

#### Scenario: 治理关闭但监控开启

- **WHEN** 启用最小监控且自动治理仍关闭
- **THEN** 系统运行只读探测并投递故障通知，不执行内容清理、政策调度或治理写操作

#### Scenario: 进程重启或重复消息

- **WHEN** 连续失败跨多个短生命周期执行或同一扫描被并发投递
- **THEN** 系统保留连续失败与最近成功的技术状态，达到阈值时形成一个当前故障，恢复后发出受控恢复通知

### Requirement: 语音故障观测不采集内容且区分正常结束

系统 MUST 记录允许的语音连接失败、重连失败、异常断开和音轨订阅失败类别，以及诊断所需阶段、耗时、平台和应用版本；连接状态变化 MUST 可作为有界技术上下文使用。主动离房、成员移除和房间正常结束 MUST 不被误判为程序故障，正常网络重连 MUST 不直接触发高优先级告警。观测 MUST 不采集房间成员身份、房间消息、音轨内容或 LiveKit 凭证，也不改变资格确认、重连和麦克风控制。

#### Scenario: 弱网后正常重连

- **WHEN** 成员经历重连并恢复连接
- **THEN** 系统可记录归一化阶段与耗时，但不产生持续断连高优先级告警，既有成员资格确认继续执行

#### Scenario: 异常音轨订阅失败

- **WHEN** 仍具有有效成员资格的客户端无法订阅音轨
- **THEN** 系统记录允许的失败类别和技术上下文，不上传音轨、成员身份、token 或数据消息正文

### Requirement: 监控启用和验收具有明确边界

系统 MUST 支持按环境和服务独立启停，开发与测试默认不向真实生产监控发送数据；显式启用但必要配置非法时 MUST 在启用阶段安全失败且不回显配置值。关闭监控 MUST 恢复既有业务行为并停止新增外传。目标环境验收 MUST 使用实际构建和受控故障，证明错误定位、通知送达、停止/恢复识别、隐私边界和关闭路径；配置成功、本地 transport 替身或 mock 告警 MUST 不作为目标环境验收通过。

#### Scenario: 开发环境缺少监控配置

- **WHEN** 开发或测试环境未显式启用外部监控
- **THEN** 应用仍可按既有配置运行，不发送生产事件，也不要求生产上传凭证

#### Scenario: 关闭已启用的监控

- **WHEN** 通过受控配置关闭一个服务的监控并运行对应构建
- **THEN** 该服务停止新增外传，业务 API、语音与任务处理保持原有语义

#### Scenario: 只有本地验证证据

- **WHEN** 只有本地构建、替身 transport 或单元测试通过
- **THEN** 验收记录明确标注目标环境错误定位、真实通知与设备崩溃验证未完成，不宣称生产监控就绪
