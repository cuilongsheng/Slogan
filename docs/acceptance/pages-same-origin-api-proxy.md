## Risks and Pending Acceptance

- The actual Pages routing, Functions configuration/compatibility date, Render fixed origin, public network TLS and Cookie attributes are pending acceptance; the upstream address must belong to the user-controlled service, and the domain name format check does not prove ownership.
- The original Origins of both sites must be in both the CORS and OAuth allowlists of the API; temporary Pages preview domains are not automatically allowed. The API source and Google redirectUri verification are not relaxed.
- Proxy removes client forwarding/IP header and does not relax Nest trust proxy. When the trusted chain is not configured, the flow is limited according to the connection IP, and the quota may be shared; the real IP attribution and forged header of Cloudflare→Render are rejected and require public network verification.
- 90 seconds is the deadline for responding to the first packet, and there is no automatic POST replay. The body interruption after the response has been sent is sensed by the browser and the sent status cannot be overwritten.
- Render cold start and built-in real-time/safe polling recovery, Neon CU consumption, Upstash TLS/command quota/BullMQ reconnection, five accounts merged into main/independent online initialization, real Google/three-person LiveKit/webhook, backup recovery/application rollback are yet to be accepted; these items have not been checked in this round.

Agent has no database migration. Rolling back simultaneously restores website products and configurations to the verified same-origin version; closes portal maintenance when no old version is available, cannot fall back to cross-site static direct connection and declares the refresh to be valid. Account and database rollback are handled as independent changes.
