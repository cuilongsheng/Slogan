>
> 目标：用于产品开发、英文表达练习、海外社区验证，以及向海外工程师展示真实的产品思考和迭代过程。
>
> 说明：本项目本身是一个求职作品和交流载体，但“找工作”不是英语角产品中的功能。产品先解决一个真实问题：让想用英语交流、但不敢开口或容易卡住的人，能够在安全的小房间里持续说话。

## 1. 产品概述

### 1.1 一句话介绍

一个预约制、由真人参与的 2–6 人英语语音交流房。用户根据英语水平和主题进入合适的房间，遇到表达困难时可以用母语文字或语音请求 AI 给出目标语言表达建议；房间结束后，系统自动沉淀关键词和个人表达记录，帮助用户下次继续开口。

### 1.2 要解决的问题

很多人并不是没有英语知识，而是缺少一个低压力、可预期、有人管理的真实交流环境：

- 不敢在公开场合开口；
- 找不到水平和兴趣相近的交流对象；
- 交流时卡住，无法把想法表达出来；
- 上完一次课或参加一次活动后，没有形成可复习的积累；
- 担心陌生人骚扰、敏感话题和不安全的语音房。

产品不以系统教学、全程纠错或替代真人交流为目标，而是帮助用户“先说出来，并且愿意下次再来”。

### 1.3 产品原则

1. **真人交流优先**：AI 是表达辅助，不是主持人、老师或聊天替代品。
2. **小规模、可预期**：V1 支持 2–6 人，默认建议 4–6 人，降低开口压力并保证每个人有机会说话。
3. **安全优先**：房间必须有明确的房主和结束机制，不提供无人管理的公开语音房。
4. **隐私最小化**：默认不录音、不保存完整语音、不展示实时字幕；只保存完成产品功能所必需的数据。
5. **先验证交流闭环**：先验证“发现房间 → 进入交流 → 卡住时获得帮助 → 会后沉淀 → 再次参与”，再扩展 1v1 教学、社区和商业化。

### 1.4 “聊天系统”的范围

本产品中的“聊天”主要指临时多人语音交流，不是传统的文字聊天系统：

- 房间内的主要内容是实时语音；
- 文字仅用于系统通知、房间规则、举报、AI 私人表达辅助和会后关键词；
- 用户之间不提供文字消息、私信或群聊历史；
- 不保存完整语音、完整转写或公开聊天记录；
- 每一次语音房都是一个独立的临时会话，结束后进入会后沉淀流程。

## 2. 产品目标与非目标

### 2.1 V1 产品目标

V1 需要让一个新用户能够独立完成以下闭环：

1. 注册并填写基础资料；
2. 选择或填写英语水平、交流主题和个人偏好；
3. 浏览或预约一个合适的房间；
4. 创建房间并邀请其他人，或通过链接进入他人房间；
5. 在 2–6 人语音房中进行真人交流；
6. 遇到表达困难时，用母语文字或语音请求 AI 生成目标语言表达；
7. 由房主处理成员移除、结束房间等管理动作；
8. 交流结束后看到系统自动生成的关键词汇总，并可以选择加入自己的单词本；
9. 对不安全或不合适的行为进行举报和屏蔽。

### 2.2 不属于 V1 的内容

以下内容暂不做，避免产品从“帮助用户开口”变成泛社交平台：

- 动态、公开发帖、点赞、评论；
- 私信、站内群聊、好友私聊和复杂社交关系；
- 视频、旁听、直播；
- 随机匹配；
- 礼物、排行榜、积分体系；
- 实时字幕和实时翻译；
- AI 全程纠错、代替用户发言或自动主持；
- 专业老师/教练市场和系统化付费课程；
- 长期固定小组和社区主持人体系；
- 完整职业社交、招聘撮合和职位推荐；
- 1v1 教学、母语者辅导和付费课程。

海外社区交流和求职展示属于项目的验证与分发方式，不新增到产品内部作为 V1 功能。

## 3. 目标用户

### 3.1 核心用户

V1 不限制用户的职业或国籍，但重点观察以下用户群体：

- **想练习真实交流的中级英语使用者**：有一定词汇和阅读能力，但缺少稳定的口语环境；
- **害怕开口的学习者**：担心犯错、卡住或被评价，需要更小、更安全的交流场景；
- **希望使用英语进行工作交流的工程师及远程工作者**：想练习自我介绍、技术讨论、远程会议和日常协作。

### 3.2 次要用户

- 高水平英语使用者：可以自然交流，也可能愿意帮助房间保持交流质量；
- 想认识海外工程师的开发者：通过主题房进行跨地域、非强社交的交流。

V1 不把“高水平用户必须当老师”作为默认定位，也不承诺专业英语教学效果。

### 3.3 用户任务

> 当我想用英语和真人交流，但又担心尴尬、找不到合适的人或表达卡住时，我希望进入一个水平和主题都比较匹配的小房间，在需要时得到简短的表达帮助，从而完成一次真实交流，并知道下次可以继续练什么。

## 4. 核心场景

### 场景 A：参加主题房

用户浏览房间列表，看到英语水平、主题、当前人数、开始时间和是否需要密码。用户选择合适的房间，预约或直接进入，在房间内进行交流。

### 场景 B：创建房间邀请熟人

用户创建一个房间，设置 CEFR 水平、主题、2–6 人人数上限、开始时间和可选的 4 位数字密码，通过系统分享能力发送链接给朋友或社区成员。

### 场景 C：工作英语练习

用户创建或参加“远程会议自我介绍”“技术方案讨论”“和海外同事闲聊”等主题房，在卡住时输入母语，获得一条可以直接说出来的目标语言表达。

### 场景 D：处理不安全行为

成员发现其他人发表骚扰、歧视、威胁或明显不适当的内容时，可以先屏蔽对方，并向房主举报；房主可以将其移出房间。成员也可以直接提交平台举报，供后台复核。

## 5. 核心业务模型

### 5.1 房间定位

V1 的房间是“有房主、有开始和结束、有成员上限”的临时语音空间。

- 房间分为“即时房间”和“预约房间”；
- 即时房间创建后立即开放，默认时长为 2 小时，并自动生成结束时间；
- 预约房间必须设置开始时间和结束时间，到开始时间后自动开放；
- 任意已完成资料、年满 18 岁且未被限制的登录用户都可以创建房间；
- 房主创建时必须设置英语水平和至少一个主题；
- 房主可以设置 2–6 人人数上限，默认建议 4–6 人；
- V1 不设置“无限人数”。无限人数会削弱每个人的发言机会和安全管理，也与产品的小组定位冲突；
- 2 人房间可以承载未来的 1v1 交流，但 V1 不包含付费教学或老师市场；
- 房间可以是公开可发现、链接可加入，或密码保护；
- 房主在场是房间保持可用的前提；
- 房主主动退出时，系统要求其选择一名当前在线成员接任房主；如果不选择，则默认移交给当前房间内按加入顺序排在第二位的成员（第二麦）；如果该成员已离开，则剩余成员按原加入顺序前移；没有成员可接任时关闭房间；
- 房主只是网络断开时，不立即转移房主权限；系统保留 60 秒重连窗口，重连成功后继续担任房主，超时后再按默认规则移交或关闭房间；
- 房间人数未满也可以交流，不以“必须满员”为开始条件。

### 5.2 CEFR 水平

产品使用欧洲语言共同参考框架 CEFR，而不是 A/B/C/D：

- A1–A2：基础交流；
- B1–B2：日常和工作场景交流；
- C1–C2：复杂主题和高流畅度交流。

V1 直接提供 A1、A2、B1、B2、C1、C2 选项，用户通过自评选择。后续可以再探索水平测试或主持人反馈，但不在 V1 强制验证等级。

### 5.3 主题

房主可以选择 1–3 个主题标签，并填写一句简短说明。

首批建议主题：

- 日常闲聊；
- 技术与编程；
- 远程工作；
- 求职与面试；
- 旅行与生活；
- 读书、电影与兴趣；
- 语言学习。

主题用于帮助用户选择和分享，不代表平台保证房间内一定按照该主题进行。

### 5.4 预约

预约不是课程报名，也不保证房间一定满员。它的价值是给用户一个明确的交流承诺：

- 房主设置预计开始时间；
- 用户可以预约并收到开始提醒；
- 用户仍可以在符合条件时直接加入已经开放的房间；
- 预约人数只用于展示预期参与人数和提醒，不作为房间开始条件；
- 未设置开始时间的即时房间创建后立即开放；预约房间到开始时间后自动开放，不要求房主点击“开始”；
- 房主可以取消或关闭房间；
- 预约房间到开始时间自动开放；如果房主在开始后 10 分钟内仍未进入，房间标记为爽约并自动取消/关闭，本次计入爽约次数；
- 预约超过 3 次爽约后，暂时禁用该用户的预约创建能力，但不影响其创建即时房间；
- V1 暂定在 30 天滚动窗口内累计 3 次爽约后禁用预约 7 天；平台故障或已被安全员确认的异常不计入爽约；
- V1 暂不处理候补、迟到惩罚和复杂信用分。

### 5.5 创建限制与时间冲突

- 用户可以随时创建即时房间；
- 用户最多同时拥有一个处于有效状态的即时房间和一个处于有效状态的预约房间；
- 任意两个房间的计划时间不能重叠；
- 即时房间默认时长为 2 小时；即时房间和已开放的预约房间都可以延长，每次最多 1 小时，最多延长 3 次，不需要成员同意；
- 创建或修改房间时，后端必须使用数据库事务检查时间冲突，Redis 只负责并发保护，不能作为唯一事实来源；
- 房主无法通过重复请求绕过房间数量和时间冲突限制。

## 6. 用户流程

### 6.1 新用户流程

微信/Google 登录 → 首次登录创建账号 → 完善头像、名称、性别、国籍/城市、兴趣爱好、CEFR 等级和出生年月 → 年龄校验 → 浏览房间 → 预约或加入 → 如房间启用临时语音处理则阅读说明并同意 → 麦克风权限检查 → 进入语音房（默认静音）→ 交流 → AI 辅助（可选）→ 离开或房主结束 → 自动跳转会后关键词沉淀页 → 选择内容加入单词本。

### 6.2 创建房间流程

创建房间 → 选择即时/预约 → 设置 CEFR、主题、2–6 人数上限、开始时间和结束时间、可选密码和公开方式 → 检查年龄、权限、房间数量和时间冲突 → 创建成功并按规则开放 → 复制或分享链接 → 等待成员 → 房主管理成员 → 结束房间 → 自动跳转会后关键词沉淀页。

### 6.3 加入房间流程

从房间列表或分享链接进入 → 校验已登录、18 岁以上且未被限制 → 查看房间信息和结束倒计时 → 输入密码（如有）→ 阅读并确认敏感话题规则 → 如房间启用临时语音处理则阅读说明并同意 → 检查麦克风 → 直接进入语音房且默认静音 → 用户自行打开麦克风参与交流。

### 6.4 房主结束流程

房主点击结束房间 → 二次确认 → 房间状态变为已结束 → 所有成员断开语音 → 生成本次会话的可见沉淀 → 房间不可重新加入。

## 7. 房间状态

| 状态   | 含义                               | 允许的操作                           |
| ------ | ---------------------------------- | ------------------------------------ |
| 草稿   | 房主尚未完成创建                   | 编辑、放弃                           |
| 已预约 | 已设置开始时间和结束时间，尚未开放 | 分享、取消、修改时间                 |
| 等待中 | 房间可加入，房主在线               | 直接加入、离开、邀请、举报           |
| 进行中 | 已有成员开始交流                   | 加入（未满时）、离开、AI 辅助、举报  |
| 已满   | 达到人数上限                       | 已在房间的人继续交流，新用户不能加入 |
| 已结束 | 房主结束或房主离开                 | 查看允许保留的会后沉淀、举报         |
| 已取消 | 房主取消预约                       | 查看取消原因（如有）                 |
| 已禁用 | 被管理员或安全员暂时关闭           | 查看关闭原因、等待恢复               |

关键规则：

- 房主主动退出时先提示房主移交权限；未选择时默认移交给按加入顺序排在第二位的成员（第二麦）；有人离开后，其余成员按加入顺序前移；没有合适成员时关闭房间；
- 房主网络断开时保留 60 秒重连窗口，超时后再移交或关闭；网络断开不直接等同于主动退出；
- 房间达到人数上限后不允许新成员加入；
- 房间创建后自动开放，不要求房主点击“开始”；
- 设置开始时间的房间到时自动开放；
- 用户加入后默认关闭麦克风，是否发言由用户自行决定，不需要房主逐一批准；
- 预约房间必须设置开始时间和结束时间；结束前 10 分钟向房间内所有成员展示提醒；
- 房主可以在规则允许的范围内延长房间时间：每次最多 1 小时，最多 3 次，不需要成员同意；延长结果实时同步给所有成员；
- 普通成员可以主动离开，并在房间仍开放且有空位时重新加入；
- 被房主移除的用户不能主动重新加入同一房间，只有房主主动邀请后才允许重新进入；被投诉后处于 24 小时限制、被判定违规、房间被禁用或账号被永久禁用的用户，即使收到邀请也不能重新进入；
- 用户主动退出不处罚，但可以在会后选择“不再推荐类似房间”；
- 房间结束后不能恢复原语音会话。

## 8. 功能需求

### P0：账号与个人资料

- 支持微信和 Google 账户登录；采用 OAuth 2.0/OIDC 的授权码流程，后端校验 provider 返回的身份令牌，并使用 `issuer + subject` 作为第三方账号唯一标识，不使用 email 作为唯一键；
- OAuth 登录只负责身份认证，不假设微信或 Google 一定返回可用的出生年月；首次资料初始化仍必须由用户填写出生年月；
- 支持自主注册；自主注册必须使用手机号接收一次性验证码，验证通过后才能创建账号；国际手机号验证和短信服务选择列入 `0.0.3`；
- 首次登录必须完成资料初始化后才能浏览、创建或加入房间；资料初始化至少包括头像、名称、性别、国籍/城市、兴趣爱好、CEFR 英语等级和出生年月；
- 兴趣爱好使用管理员在后台配置的“大类—小类”选项，用户可多选；
- 出生年月用于年龄校验，未满 18 岁的用户禁止进入、创建、预约或接受房间邀请；V1 采用出生年月自填加账号验证的轻量校验，不宣称具备强实名年龄证明能力；
- 根据用户当前设备语言环境选择界面语言：设备语言为中文时使用中文，其他语言默认使用英文；
- V1 只支持中文和英文界面，不支持切换到其他语言；
- 用户可以在设置中查看当前界面语言，并在中文/英文之间手动切换；手动选择优先于设备默认语言；
- 不要求用户公开真实姓名、公司或联系方式；
- 用户可以修改自己的资料和隐私设置，但出生年月修改需要重新进行年龄校验；
- 用户注销时采用软删除，正常业务页面不再展示；管理员/安全员可以在独立的受限页面查看已注销和永久禁用用户的必要数据；

### P0：房间发现与创建

- 展示公开房间列表；
- 列表至少展示房间类型、主题、CEFR、当前人数/上限、开始时间、结束时间、房主昵称和密码状态；
- 支持按 CEFR、主题和状态筛选；
- 支持创建即时房间和预约房间；
- 预约房间必须设置开始时间和结束时间；
- 支持创建、编辑、取消和结束自己的房间；
- 只有已完成资料初始化、年满 18 岁且未处于平台限制状态的用户可以创建房间；
- 支持生成分享链接；
- 支持可选的 4 位数字密码；
- 公开房间允许符合条件的用户直接加入，不要求房主逐一确认；
- 创建或修改房间时阻止房主的有效房间发生时间重叠；
- 房间创建后必须明确显示“公开可发现”或“仅通过链接加入”。

### P0：预约

- 用户可以预约尚未开放的房间；
- 房主和已预约成员可以看到预约人数；
- 在开始前提供一次提醒；
- 预约房间结束前 10 分钟，向房间内所有成员展示倒计时提醒；
- 房主可以取消预约；
- 房主可以在规则允许的范围内延长房间时间，新的结束时间同步给所有成员；
- 预约取消或房间关闭时，向已预约用户展示状态变化；
- 房主在 30 天滚动窗口内累计 3 次爽约后，禁用预约创建 7 天，但仍可创建即时房间。

### P0：语音房

- 使用 LiveKit Cloud 提供实时语音；
- 后端只负责鉴权和发放短期 token，不自建 RTC 层；
- 进入前检查麦克风权限和设备状态；
- 进入房间前展示敏感话题和行为规范提示，至少包括政治、色情、赌博、毒品、违法经济活动、人身攻击、骚扰、歧视和威胁；
- 用户必须确认已阅读房间规则后才能进入语音房；
- 进入房间后继续展示可打开的规则入口，用户可以随时查看；
- 中文界面展示中文规则，英文界面展示英文规则；敏感话题规则的含义保持一致，不因语言变化而放宽；
- 支持静音/取消静音和离开房间；
- 用户加入房间时默认静音，用户自行决定何时打开麦克风；
- 展示成员昵称、CEFR 和麦克风状态；
- 展示房主身份；
- 网络异常时提供重连、退出和错误提示；
- 即时房间默认时长为 2 小时，并展示明确的结束倒计时；
- 房主主动退出时提供成员选择器，用于指定新的房主；未指定时按规则默认移交；
- 房主网络断开时保留 60 秒重连窗口，避免短暂网络问题直接触发权限转移；
- 房主每次最多延长 1 小时，最多延长 3 次，不需要成员同意；延长后的结束时间同步给所有成员；
- 房间结束前 10 分钟展示全员可见的结束提醒；
- 不支持录音、视频、旁听和公开回放。

### P0：房主管理

- 房主可以查看当前成员；
- 房主可以将成员移出当前房间；
- 移除时可以选择简单原因：骚扰、敏感/违法内容、广告、破坏交流或其他；
- 被移出的用户不能主动重新加入同一房间，只有房主主动邀请后才允许重新进入；
- 房主可以结束房间；
- 房主主动退出时可以移交房主权限；没有可接任成员时关闭房间；
- 房主网络断开超出 60 秒后按默认规则移交或关闭房间；
- 房主可以延长当前房间的结束时间，并向全体成员同步结果。

### P0：安全、举报和屏蔽

- 用户可以屏蔽其他成员；屏蔽后不再看到对方的资料，并尽可能降低继续互动的机会；
- 用户可以向房主举报成员；
- 用户可以向平台提交举报，填写类别和文字说明；
- 举报记录至少保存房间 ID、举报人、被举报人、时间、举报类别、房主处理结果和相关系统日志；
- 举报严重程度分为一般、严重和高危：一般包括广告、跑题和轻度攻击；严重包括骚扰、歧视和威胁；高危包括违法、未成年人风险和现实人身安全风险；
- 单条投诉不会自动触发处罚；安全员确认投诉达到处理条件后，才可以对成员/房主执行临时限制；
- 临时限制按安全员判定等级执行：一般限制 3 小时，严重限制 12 小时，高危限制 24 小时；限制期间不能进入其他房间、创建房间、预约或接受邀请；
- 用户可以在限制生效后 30 分钟内提交一次申诉；安全员有权提前解禁，解禁后相关功能立即恢复；未提前解禁时，限制到期自动恢复；
- 严重或高危事件在事实清楚并经安全员确认后，可以直接永久禁用相关账号；永久禁用用户不能通过房主邀请重新加入；
- 平台不保存完整录音。由于不录音，后台不能承诺对所有语音举报进行完整复原；
- 对于高风险举报，后台可以保留必要的事件元数据、短期风控信号或用户主动提交的文字说明，具体保存周期需结合实际地区法规确认；
- V1 对语音进行临时识别，仅用于敏感词和高风险表达的即时提示；不保存录音，也不保存完整转写；
- 触发风险规则时，只向房主发出风险提醒，由房主判断是否移除或举报，不因单个关键词自动封禁；
- 平台可以对明显的辱骂、威胁、骚扰、广告和违法风险进行规则提示或拦截；
- 敏感词识别必须设置误判处理、频率限制、供应商数据删除策略和降级方案；识别服务失败时，语音房仍可继续使用，但安全能力降级并记录事件。

### P0：AI 表达辅助

AI 只在用户主动操作时工作：

- 用户可以输入母语文字，或主动录制一段母语语音；
- 母语语音只用于本次 AI 请求，处理完成后删除临时音频，不作为房间录音；
- 系统返回一条适合当前主题和英语水平的目标语言表达；
- 优先返回自然、简短、可以直接说出口的句子；
- 可以提供 1–2 个替代表达，并标注语气差异；
- 用户决定是否使用，AI 不自动播放、不代替用户发言；
- AI 输出显示为文字，不作为实时字幕，也不自动发送给房间其他成员；
- 必须明确提示 AI 可能出错，用户应自行判断；
- 不默认保存用户输入和 AI 输出到公开内容中。

### P0：会后沉淀

V1 自动生成轻量的房间级关键词汇总，但不保存完整对话记录：

- 会话结束后，系统根据临时语音识别结果生成关键词和常用表达；
- 汇总只展示主题、关键词和表达，不展示具体成员或完整原句；
- 用户可以从汇总中选择内容加入自己的单词本；
- 用户可以编辑、删除和收藏自己的单词本内容；
- 临时音频和完整转写在处理完成后删除，不作为历史聊天记录；
- 如果用户关闭会后沉淀或处理失败，房间仍可以正常结束；
- 不保存或展示其他成员的私人表达内容，除非获得明确同意。

### P1：邀请与分享

- 分享链接包含房间标识，不直接暴露成员隐私；
- 链接打开后先展示房间信息，再要求登录或输入密码；
- 支持系统分享面板，覆盖 Discord、Reddit、X 等外部渠道；
- 支持用户主动添加好友，形成轻量好友列表；
- 添加好友必须经过对方同意，单方面发起不直接建立好友关系；
- 好友列表只用于查看可邀请/空闲状态和发起房间邀请，不提供私信和站内群聊；
- 空闲状态定义为“当前不在任何房间”，不要求用户主动开启；陌生人可以看到用户是否空闲，但不能看到精确在线时长或位置；
- 房主可以从好友列表或当前在线的可邀请用户中发出房间邀请。

### P1：后台接口

- 后台采用最小权限角色，不允许所有后台账号默认拥有全部能力；
- 支持查看平台汇总数据：房间数、总成员数、当前在线人数、平均房间时长、预约数和活跃用户趋势；
- 国籍/地区和 CEFR 使用用户主动填写的数据；平台管理员可以查看全部相关数据，其他后台角色按最小权限访问；
- 活跃用户排名只供授权管理员内部分析，不在前台公开，不作为用户奖励或惩罚依据；
- 支持查看所有房间列表、房间状态、成员、敏感风险事件和举报证据包；
- 安全员可以向房主发送提醒、发出警告、临时禁用房间并填写具体原因；
- 安全员可以恢复尚未到结束时间且经复核允许恢复的房间；已结束房间不可恢复；
- 房间被后台禁用时，所有成员收到明确的关闭原因，房间进入“已禁用”状态并记录操作者；
- 举报任务暂定按安全员当前待处理任务数最少优先分配；任务数相同时使用轮询，避免长期集中到单个安全员；
- 临时限制、提前解禁和申诉处理只能由具备安全员权限的账号执行；必须填写等级、原因、生效时间和处理结果；
- 安全员可以执行 3/12/24 小时临时限制，并在事实清楚时执行严重/高危事件的永久禁用；平台管理员负责查看全量数据、角色管理和审计，不直接替代安全员执行案件处理；
- 平台管理员在 V1 暂定只有一个账号；安全员可以配置多个账号；管理员可以查看平台全部业务数据，但不能查看密码、密钥、完整录音或不存在的完整转写；管理员账号可以同时授予安全员角色，但所有案件动作仍按安全员权限和审计规则执行；
- 后台不能查看不存在的录音或完整转写，不能读取 LiveKit API secret、用户密码等敏感凭证；
- 所有后台操作必须记录操作者、角色、时间、目标对象、动作、原因和结果。

#### 后台角色

| 角色       | 权限范围                                                    |
| ---------- | ----------------------------------------------------------- |
| 平台管理员 | 平台配置、角色管理、汇总数据、用户/房间限制、解封和安全审计 |
| 安全员     | 举报证据包、敏感事件、房间提醒/警告/禁用/恢复、成员限制建议 |
| 运营分析员 | 只读汇总指标和趋势，不查看举报正文、成员敏感资料或执行处罚  |
| 审计员     | 只读后台操作日志和处理结果，不能修改业务数据                |

## 9. 安全与隐私设计

### 9.1 房间安全边界

- 所有房间都有房主；
- 没有房主在线时，房间自动结束；
- 新建房间默认采用有限人数；
- 公开房间必须可以被房主管理；
- 高风险用户或重复违规用户可以被平台限制创建和加入房间；
- 加入语音房前展示社区行为规范和举报入口。
- 加入语音房前必须确认敏感话题规则；拒绝确认时不能进入房间；
- V1 只允许年满 18 岁的用户进入、创建、预约或接受房间邀请；年龄依据用户填写的出生年月校验；
- 被安全员施加临时限制的用户，可以在限制生效后 30 分钟内提交申诉；安全员确认无误后提前解禁，未提前解禁时限制期结束自动恢复；
- 严重或高危事件在事实清楚并经安全员确认后永久禁用账号；
- 敏感话题提示是行为边界和风险提醒，不等于系统能够识别或阻止所有违规内容；

### 9.2 不录音的取舍

不录音降低隐私风险和运营成本，但也意味着平台无法像录音型产品一样事后完整调查语音事件。因此 V1 必须明确：

- 举报处理依赖用户描述、房主处理、时间和房间成员元数据；
- 对严重违规行为可以采用即时移除、限制加入和平台封禁；
- 不向用户承诺“所有语音内容都可被平台复核”；
- V1 采用小范围、临时的语音转文字识别进行敏感词提醒；上线前必须验证隐私、准确率、成本、误判处理和供应商删除策略。

### 9.3 数据最小化

保存：账号必要信息、房间配置、参与关系、预约状态、举报记录、封禁/限制/申诉记录、用户主动保存的表达，以及不含成员归属的房间级关键词汇总。

默认不保存：完整录音、完整语音转写、临时 AI 音频、未确认的完整会话摘要、其他成员的私人资料。

- 账号注销采用软删除，普通用户和公开业务页面不再展示该账号；
- 举报、处罚、申诉和审计所需的数据不因注销立即物理删除；平台管理员和授权安全员可以在独立的受限页面查看已注销、永久禁用用户的必要数据；
- 临时音频、临时转写和 STT 供应商侧的处理数据最长保留 1 周，优先在本次处理完成后立即删除；举报、处罚、申诉和审计数据不适用这一临时数据期限，另行制定保留规则；
- 具体导出和彻底删除规则在隐私政策中单独确定。

### 9.4 临时语音处理与用户同意

- “不录音”指平台不保存和回放完整房间音频；为安全提醒、AI 语音输入和会后关键词汇总，音频可能被实时或短时发送给 STT 服务处理；
- 用户第一次加入支持临时语音处理的房间前，必须看到简明说明：处理目的、处理范围、不会保存完整录音/转写、服务商类别和处理失败后的影响；
- 用户明确同意后才能加入该类房间；V1 暂不提供关闭语音识别但继续加入同一房间的模式；
- AI 短语音和房间实时识别结果只保留在本次处理链路中，处理完成后删除；
- 用户主动触发 AI 语音输入时，需要再次看到该请求的处理提示；
- 用户可以在设置中查看当前同意状态并撤回未来的处理同意；已开始的房间处理以当前会话规则完成或停止，不追溯保存历史音频；
- STT V1 优先选择有免费额度或低成本试用的服务商，通过适配器接入，并设置额度上限和超额停用策略；“免费”不作为长期可用或无成本的承诺；
- 临时音频、临时转写和供应商侧数据最长保留 1 周，优先在处理完成后立即删除；任何 STT 供应商的实际留存、跨境传输和删除能力必须在接入前确认，并写入隐私政策。

### 9.5 举报取证方案

在不保存完整录音的前提下，V1 使用“事件证据包”处理举报：

- 举报内容：举报人、被举报人、房间、时间、举报类型、用户文字说明和提交渠道；
- 房间上下文：当时在线成员、房主、房间状态、加入/离开时间、被移除记录和房主处理动作；
- 风险事件：敏感规则类别、触发时间、说话者的内部用户 ID、识别置信度和是否向房主发送提示；不保存原始音频和完整转写；
- 关联信号：同一房间的多次举报、同一账号的历史举报/移除/封禁记录和异常加入行为；
- 处理记录：分配的安全员、处理时间、提醒/警告/禁用/恢复动作、处理理由和申诉结果；
- 证据包默认只对相关安全员和具备权限的管理员可见，并记录每次查看和修改；
- 单个关键词、单个举报或单次房主移除不直接触发永久封禁；严重威胁、未成年人风险或明显违法风险可以先暂停房间，再由安全员复核；
- 举报不保证可以还原完整对话，平台在举报页面明确说明这一限制。

## 10. 关键指标

V1 不以注册量作为唯一目标，重点观察真实交流闭环：

### 激活指标

- 注册后完成资料设置的比例；
- 注册后首次加入或创建房间的比例；
- 首次成功进入语音房的比例。

### 核心体验指标

- 完成至少 5 分钟真人交流的用户比例；
- 一次房间的平均有效交流时长；
- AI 辅助使用后继续完成交流的比例；
- 房间结束后保存至少一条表达的比例。

### 留存与分发指标

- 7 天内再次加入或创建房间的比例；
- 房间分享链接打开到加入的转化率；
- 预约后实际进入房间的比例；
- 用户主动反馈的“更敢开口”或“愿意再次使用”比例。

### 安全指标

- 举报处理时长；
- 被移除和被举报的重复用户数；
- 房主处理举报的完成率；
- 误判和滥用举报数量。

“找到工作”是项目层面的长期结果，不作为产品 V1 的 KPI。可以通过公开开发日志、英文产品介绍、社区讨论和技术复盘来观察它是否带来海外工程师交流与求职机会。

## 11. 技术边界

### 客户端

- React Native + Expo + TypeScript；
- 移动端优先；
- 负责登录状态、房间列表、预约、语音房 UI、AI 请求和会后沉淀展示。

### 服务端

- NestJS + TypeScript；
- Prisma + PostgreSQL；
- Redis 用于短期状态、限流、房间事件或队列场景；
- 后端负责用户、房间、预约、成员关系、权限、举报、AI 请求和审计日志。

### 实时语音

- 使用 LiveKit Cloud；
- 服务端签发限定房间和短期有效期的 token；
- 普通成员 token 只允许加入指定房间、订阅音频、发布麦克风音频和必要的房间数据；默认静音由客户端控制，不等于没有发布权限；
- 房主也通过后端鉴权获得普通语音权限，房主管理、移除成员和结束房间由 NestJS 校验后调用 LiveKit Server API，不把平台管理员权限放进客户端；
- 不向普通用户发放 roomCreate、roomList、roomRecord 或平台级管理权限；
- 房间级 STT worker/agent 使用只订阅权限进入房间，只能接收需要处理的音频，不能发布音频、不能管理房间、不能录音；
- token 中只使用不可反推个人身份的用户 ID，不把真实姓名、邮箱或手机号写入 LiveKit identity 或 room name；
- 通过 LiveKit webhook 接收 participant joined/left、connection aborted 和 room finished 事件，作为房间状态和审计记录的补充来源；
- 被移除成员需要同时更新应用数据库和 LiveKit 连接状态，阻止其使用旧 token 重入；
- 不自建 RTC 层；
- V1 不录音、不做回放。

### AI

- AI 请求必须经过后端，避免在客户端暴露密钥；
- 支持母语文字输入和用户主动触发的短语音输入；
- 短语音只进入本次识别和生成流程，处理完成后删除；
- AI 语音输入和房间安全识别使用 STT（Speech-to-Text，语音转文字），具体供应商 V1 暂定为可替换适配器，不在业务代码中绑定单一服务；
- STT 供应商必须支持流式识别、目标语言覆盖、明确的数据删除/不留存策略和可接受的延迟；
- 会后关键词汇总使用临时语音识别结果生成，保存前去除成员归属和完整原句；
- 需要设置超时、失败提示和频率限制；
- AI 输出不应阻塞真人语音交流；
- 应记录必要的调用状态和成本信息，但默认不长期保存用户原始表达；
- 语音识别或 AI 服务失败时，房间和真人语音交流仍然可用；
- AI 翻译失败时优先提供“重试”和母语文字输入，不自动替换为质量未知的第二个模型；
- AI 语音输入失败时回退到文字输入；会后关键词生成失败时展示“本次沉淀暂不可用”，不阻塞关闭房间；
- 敏感词识别失败时向安全员记录“安全能力降级”事件，但不自动处罚用户。

## 12. V1 验收标准

一个完整的 V1 至少需要通过以下真实流程验证：

1. 新用户可以注册、登录并完成 CEFR 和主题设置；
2. 用户可以创建公开房间、链接房间和密码房间；
3. 用户可以浏览、筛选、预约并通过分享链接加入房间；
4. 房间在未满员时可以开始，满员后不能继续加入；
5. 至少两名用户可以通过 LiveKit 完成稳定的语音交流；
6. 房主可以查看成员、移除成员并结束房间；
7. 房主离开后房间会按规则结束，不留下无人管理的语音房；
8. 用户可以主动输入母语文字或录制母语语音，请求 AI 将想法转换为自然的目标语言表达；
9. AI 失败、超时或限流时，用户仍可以继续语音交流；
10. 用户可以屏蔽、举报，后台可以查看并处理举报记录；
11. 房间结束后，用户可以查看自动生成的房间级关键词汇总，并选择内容加入自己的单词本；
12. 不产生录音、公开完整转写或未经确认的完整会话记录；临时音频和转写处理完成后删除；
13. 关键权限和房间状态在直接请求接口时同样受到服务端保护，而不只依赖客户端 UI；
14. 房主主动退出时可以指定接任成员，未指定时系统按默认规则移交；房主短暂断网不会立即触发移交；
15. 被移除成员无法主动重入，只有房主主动邀请后才能重新加入；
16. 房间人数并发加入时不会超过 2–6 人上限；
17. 预约房间自动开放，结束前 10 分钟所有房内成员可看到提醒，房主延长时间后所有成员同步新时间；
18. 预约房主达到爽约阈值后无法创建预约，但仍可以创建即时房间；
19. 用户在加入支持临时语音处理的房间前可以看到说明并完成同意；
20. 敏感词提醒只向房主发出，STT 失败时房间继续可用且安全员收到降级事件；
21. 举报可以生成包含时间、成员、风险事件和房主管理动作的事件证据包；
22. 管理员和安全员只能执行自己角色允许的后台动作，所有处理都有原因和审计记录。

## 13. 海外社区验证与求职路线

这个项目的外部传播不是上线后的附属工作，而是产品验证的一部分。

### 13.1 每次对外交流带什么

- 一句话产品介绍；
- 当前版本截图或短视频；
- 一个具体问题，而不是泛泛地问“你觉得怎么样”；
- 当前已实现、正在验证和暂不支持的边界；
- 用户反馈后的改动记录。

### 13.2 优先验证的问题

- 不同用户是否愿意参加 2–6 人的陌生人英语语音房，以及哪种人数最适合他们；
- CEFR 和主题标签是否足够帮助用户选择房间；
- 预约是否真的提高参与承诺；
- 用户更需要 AI 翻译、改写，还是话题提示；
- 不录音的安全机制是否让用户感到足够可信；
- 房间由普通用户创建时，房主管理负担是否过高；
- 临时语音识别用于敏感词提醒和会后关键词汇总，是否能在隐私可接受的前提下提供足够价值。

### 13.3 对外表达方式

产品介绍可以使用英文：

> I’m building a small, host-led English voice room for people who want to speak more but feel stuck or nervous. The room is limited to a few real participants, and AI only helps when someone cannot find the right words.

交流时重点展示真实过程：创建房间、邀请用户、进入语音房、触发 AI 辅助、处理举报和会后复盘。不要把尚未实现的审核能力、用户规模或求职结果写成已完成事实。

## 15. V1 已确定的产品决策

本节记录已经确定的 V1 规则。后续如果要修改，应同步更新用户流程、房间状态、验收标准和技术设计。

### 15.1 房间规模

- V1 支持房主设置 2–6 人上限；
- 默认建议 4–6 人，以保证交流质量；
- V1 不支持无限人数；
- 2 人房间为未来 1v1 交流预留能力，但不包含付费教学、母语者辅导或老师市场；
- 1v1 教学和付费场景属于 V2 以后方向。

### 15.2 加入和开放规则

- 公开房间允许符合条件的用户直接加入，不需要房主逐一批准；
- 用户进入房间时默认关闭麦克风；
- 用户可以自行打开或关闭麦克风；
- 设置密码的房间必须输入正确的 4 位数字密码；
- 房间创建后立即开放；如果设置了开始时间，则到时间后自动开放，不要求房主点击“开始”；
- 房主在线是房间继续存在的前提；主动退出先移交房主权限，网络断开先进入 60 秒重连窗口，超时后按默认规则移交或关闭房间；
- 未满 18 岁、未完成资料初始化或处于平台限制状态的用户不能加入房间。

### 15.3 英语水平

- 使用 CEFR 的 A1、A2、B1、B2、C1、C2 作为可选等级；
- 用户通过自评选择，不在 V1 强制考试或自动评级；
- 房间列表直接展示房主设置的 CEFR 等级。

### 15.4 AI 输入和输出

- V1 同时支持母语文字输入和母语短语音输入；
- AI 只在用户主动请求时工作；
- AI 输出简短、自然、可以直接说出口的目标语言表达；
- AI 不自动播放、不代替用户发言，也不作为实时字幕；
- 用户主动录制的短语音只用于本次 AI 处理，处理完成后删除，不作为房间录音。

### 15.5 安全控制

- 安全属于 V1 P0；
- 每个房间都有房主，由房主自主管理成员；
- 房主可以移除违规成员，成员可以屏蔽和举报；
- V1 支持临时语音识别，用于敏感词和高风险表达提醒；
- 触发提醒后由房主判断是否移除或举报，不因单个关键词自动封禁；
- 平台保存房间、成员、举报和处理动作等事件数据，但不保存完整录音或完整语音转写；
- 一般、严重、高危举报分别用于常规处理、重点审核和紧急风险处理；
- 单条投诉不会自动触发处罚；安全员确认达到处理条件后，按一般/严重/高危等级施加 3/12/24 小时临时限制，限制其进入、创建、预约和接受邀请；用户可以在限制生效后 30 分钟内申诉，安全员确认后提前解禁；
- 严重或高危事件事实清楚并经安全员确认后，永久禁用账号；
- 重复违规由后台结合证据和历史记录进一步限制或封禁，不因单个关键词自动处罚。

### 15.6 会后沉淀

- 会后自动生成不含成员归属的房间级关键词汇总；
- 用户可以从汇总中选择内容加入自己的单词本；
- 用户可以编辑、删除和收藏自己的单词本内容；
- 不保存完整谈话记录、完整转写或其他成员的私人表达。

### 15.7 用户范围

- 产品不限制用户的职业、国籍或身份；
- 英语学习者、工程师、远程工作者和希望进行跨文化交流的用户都可以使用；
- 对外验证时可以分别观察不同用户群体的使用动机和留存，不把某一类人永久定义为唯一目标用户。

### 15.8 房主机制

- 不依赖人工主持人；
- 先验证普通用户作为房主时，能否通过简单的移除、举报和结束房间能力完成基本管理；
- 房主不能自动获得平台封禁权限，平台级处罚由后台处理。

### 15.9 房主断开与权限移交

- 房主主动点击退出时，必须先选择是否将房主权限移交给当前在线成员；
- 如果房主没有选择，默认移交给按加入时间排序的第二位已加入成员，即第二麦；房间成员展示当前麦顺序，成员离开后其余成员按加入顺序前移；
- 如果没有可接任成员，房间关闭；
- 房主只是网络断开时，系统保留 60 秒重连窗口，不立即移交权限；
- 房主在 60 秒窗口内重连，继续保留房主权限；超时后按默认成员移交规则处理；
- 所有权限移交、关闭和断开事件都写入审计日志。

### 15.10 预约、爽约与时间限制

- 即时房间创建后立即开放；预约房间必须设置开始时间和结束时间，到开始时间自动开放；
- 房主最多同时拥有一个有效即时房间和一个有效预约房间，两个房间的时间不能重叠；
- 即时房间默认时长为 2 小时；房主可以在房间内延长，每次最多 1 小时，最多 3 次，不需要成员同意；
- 预约房间结束前 10 分钟向所有房内成员展示倒计时；
- V1 暂定房主在 30 天内累计 3 次未在开始后 10 分钟内进入预约房间，记为爽约；
- 累计达到阈值后，禁用预约创建 7 天，但不影响即时房间；
- 平台故障或安全员确认的异常不计入爽约。

### 15.11 加入、满员与移除

- Redis 使用原子操作或 Lua 脚本保护加入名额，数据库事务负责最终保存成员关系；
- 房间达到人数上限后拒绝新的加入请求；
- 被移除成员不能主动重新加入同一房间；
- 只有房主主动邀请被移除成员时，系统才允许其重新加入；
- 普通成员主动离开后，在房间仍开放且有空位时可以重新加入；
- 房主邀请也必须经过后端检查，包括房间未结束、成员没有 24 小时限制、没有被判定违规、账号没有被永久禁用和房间仍有名额；
- 被投诉后受临时限制、被禁用、被判定违规或被永久禁用的用户不能通过房主邀请绕过限制。

### 15.12 STT 与同意机制

- STT 是 Speech-to-Text，即把语音临时转换成文字，用于敏感词提醒和会后关键词生成；
- V1 不保存房间录音和完整转写，临时音频/转写处理完成后删除；
- 临时音频、临时转写和 STT 供应商侧数据最长保留 1 周，优先在处理完成后立即删除；
- 用户首次进入支持临时语音处理的房间前，必须看到处理目的和数据删除说明并明确同意；
- 用户拒绝同意时，V1 暂不允许加入需要 STT 的房间；
- 敏感词触发只提醒房主，不因为单个关键词自动封禁；
- 具体 STT 供应商暂不写死，优先选择有免费额度的服务商，通过可替换适配器接入，并验证延迟、准确率、成本和数据留存策略；免费额度耗尽或服务停止时必须降级，不得阻塞房间。

### 15.13 AI 与 STT 降级

- AI 翻译失败时提供重试和母语文字输入；
- AI 母语语音输入失败时回退到文字输入；
- STT 敏感词识别失败时，房间继续使用，向安全员记录安全能力降级事件；
- 会后关键词生成失败时展示不可用提示，不阻塞关闭房间；
- 所有失败都记录请求状态和错误类型，但不保存原始音频和完整转写。

### 15.14 举报取证与安全员分配

- 举报证据由举报信息、房间成员时间线、敏感风险事件、房主管理动作和账号历史风险组成；
- 不保存完整音频和完整语音转写，平台不承诺还原全部对话；
- 举报任务暂定分配给当前待处理任务最少的安全员，同数时轮询；
- 安全员可以提醒房主、发出警告、临时禁用房间和提交平台处罚建议；
- 安全员不能直接修改用户密码、读取 LiveKit secret 或查看不存在的录音；
- 所有查看、分配、处理、恢复和处罚动作必须记录操作者、时间、原因和结果。

### 15.15 管理员与安全员

- 平台管理员可以查看平台汇总数据、房间和用户风险状态，管理角色、封禁和恢复；
- 安全员可以查看举报证据包、敏感事件和房间状态，执行提醒、警告、禁用和恢复；
- 运营分析员只查看聚合指标，不查看举报正文和成员敏感资料；
- 审计员只读后台操作日志；
- 平台管理员可以查看平台全部用户、房间、国籍/城市、CEFR、在线时长和活跃排名数据；安全员只能查看处理案件所需的数据；这些数据不在前台公开；
- 平台管理员 V1 暂定为单一管理员账号，安全员可以有多个账号；管理员与安全员的每次查看和操作都必须留有审计记录；
- 房间被安全员或管理员禁用时必须填写关闭原因；未到结束时间且复核通过的房间可以恢复，已结束房间不可恢复。

### 15.16 V1 产品结构

- 当前开发顺序以“创建/加入房间 → 真人语音交流 → 房主管理 → 关闭房间 → 会后关键词沉淀”为第一闭环；
- 预约、新建房间、空闲人员、好友邀请、房间/预约历史、单词本和会后跳转在核心语音闭环稳定后逐步扩展；
- 好友功能只用于查看可邀请/空闲状态和发送房间邀请，不提供私信和站内群聊；
- 好友关系必须双方同意；空闲状态定义为用户当前不在任何房间，陌生人可以看到该状态；
- 1v1 教学、母语者辅导、付费和职业化功能仍属于 V2 以后方向。

## 16. 0.0.1 开发范围

`0.0.1` 是第一个可运行的技术验证版本，不代表完整 V1，也不对外承诺全部功能。

### 16.1 目标

验证最核心的语音交流闭环：

```text
微信/Google 登录 → 首次完善资料并完成 18 岁校验 → 创建即时房间 → 另一名用户加入 → 双方完成 LiveKit 语音交流
→ 房主移除/邀请成员 → 房主主动退出并移交或关闭
→ 房间结束 → 成员看到结束结果
```

### 16.2 必须实现

- 支持中文/英文界面文案和敏感话题规则文案；
- 微信/Google 登录；首次登录创建账号并完成头像、名称、性别、国籍/城市、兴趣、CEFR 和出生年月资料；
- 年龄校验：未满 18 岁不能进入、创建或接受房间邀请；
- 根据手机系统语言选择中文/英文界面；除中文外的系统语言默认使用英文；
- CEFR 等级和主题设置；
- 创建即时房间，支持 2–6 人上限，默认时长 2 小时；

### 16.4 0.0.1 验收场景

1. 用户 A 创建一个 2 人公开即时房间；
2. 用户 B 使用中文或其他系统语言打开客户端，界面分别显示中文或英文；
3. 用户 B 从列表加入，进入前能看到敏感话题规则并确认，加入后默认静音；
4. 用户 B 拒绝确认规则时不能进入房间；
5. A 和 B 都能正常发布/订阅麦克风音频；
6. A 移除 B，B 被断开且不能主动使用旧 token 重入；
7. A 邀请 B，B 在房间未结束且有空位时可以重新加入；
8. A 主动退出并指定 B 接任，B 成为新房主；
9. 房主不指定接任者时，系统按默认顺序移交给下一位在线成员；
10. 房主短暂断网并在重连窗口内恢复，房间不发生权限转移；
11. 房主断网超时后，系统按规则移交或关闭房间；
12. 两个并发加入请求在房间只剩一个名额时，最多只有一个请求成功；
13. 房间结束后，所有成员收到结束通知，房间不可普通加入；
14. 举报、移除、移交、断开和结束事件都能在后台或日志中追踪。
15. 首次登录用户必须完成资料初始化；未满 18 岁用户无法创建或加入房间。

## 17. 仍需完善的业务规则

以下内容不阻塞 `0.0.1` 的核心语音房开发，但在邀请陌生用户进行公开测试前需要确定。

### P0：公开测试前必须确定

- 临时限制的案件处理条件、证据最低要求和安全员操作手册；单条投诉不自动触发处罚；
- 临时限制的起算点、自动恢复任务和安全员申诉处理时限；当前已确定申诉提交窗口为限制生效后 30 分钟；

- 微信/Google 登录失败、取消授权、头像/昵称获取失败时的降级流程；
- 出生年月修改、时区处理和用户年龄校验失败时的提示与申诉流程；
- V1 是否接受用户自填年龄而不做证件验证，以及发现虚假年龄后的处理规则；
- 最终 STT 供应商、临时数据删除证明、跨境传输说明和隐私政策文案；
- 密码错误、分享链接滥用、频繁加入/退出和重复举报的限流规则；
- 账号注销、举报/处罚/申诉数据的保留期限和管理员受限查看流程；
- 管理员单账号丢失、转交和安全员账号回收机制。
- 永久禁用是否允许申诉，以及申诉通过后的恢复范围；
- 房主在 60 秒重连窗口内断开时，现有成员是否继续交流、是否暂停新成员加入；建议现有成员可继续交流但暂停新加入；
- 普通成员离开后重新加入是否重新排到麦位末尾；建议按新的加入事件排到末尾；
- 房主在房间进行中被临时限制或永久禁用时，是否立即移交房主并通知成员；建议立即触发移交规则；
- 仅有出生年月自填和手机号验证码时，年龄校验的可信等级和虚假年龄处理；手机号验证码本身不能证明年龄，0.0.3 再评估第三方年龄验证。

- 预约提醒使用站内通知、推送还是邮件；
